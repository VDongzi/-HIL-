# 「什么是HIL测试」动画视频制作过程

2026-11-04 · Dongzi Wen

## 项目概览

「什么是HIL测试」是一支 Vector好奇号 风格的科普动画，旁白原长约 10 分 40 秒，按 1.1 倍速播放约缩短 9%，用一个 HTML 网页做成，再用 Camtasia 录制为 1080p、16:9 的视频。

| 项目 | 内容 |
| --- | --- |
| 内容结构 | 开场、本期内容、4 个章节、结束页、片尾，共 36 个场景 |
| 画面 | 1920×1080 舞台，场景全部用 SVG 绘制，按旁白逐句出现 |
| 声音 | 真人录制的旁白 `assets/narration.m4a`；背景音乐和音效在浏览器里用 Web Audio 实时生成 |
| 字幕 | 按旁白时间轴逐句显示，白字黑边 |
| 品牌 | Vector 品牌色板，标题 Clash Vector / Noto Sans CJK SC Medium，正文 Inter / Noto Sans CJK SC Regular |
| 成片 | Camtasia 录屏，1080p |
| 源码 | GitHub 仓库 [VDongzi/-HIL-](https://github.com/VDongzi/-HIL-)，主文件 `HIL测试动画.html`（约 230 KB，图片和二维码已内嵌） |

四个章节为：01 什么是HIL测试、02 为什么要进行HIL测试、03 HIL测试与黑盒测试、04 HIL测试的局限。

## 动画实现

整支动画是一个独立的 HTML 文件，不依赖任何框架；每个场景是一段 SVG，里面的元素按旁白的第几句依次出现。

- **舞台：** 1920×1080，按窗口大小等比缩放。左上角是章节名，右上角是 VECTOR 字样，底部是字幕和红色进度线。
- **场景：** `scenes` 数组里的每一项对应一个画面，写明章节名 `ch`、字幕 `cues` 和 SVG 内容；还可以标记白底、深色或渐变背景。
- **出现动画：** 元素用 `R(第几句, 内容, 动效)` 包装，到那句旁白时自动出现。动效有上浮、左右滑入、弹出、淡入、横向展开和描线绘制，可单独设延迟。
- **场景内交互：** 需要精确时机的画面用 `hook` 函数控制，例如温度计从 38°C 降到 22°C、按钮被按六次、汗珠逐个消失。
- **绘图小工具：** 文字 `T()`、卡片 `B()`、箭头 `A()`、汽车 `car()`、电路板 `pcb()`、控制器 `acCtrl()` 等函数反复使用，保证各场景风格一致。`T()` 会按字重自动选标题或正文字体。
- **控制栏：** 播放、上一句/下一句、进度条、倍速、旁白/音乐/音效开关、隐藏控件、全屏和导出。快捷键：空格播放，F 全屏，H 隐藏控件，← → 逐句切换。
- **预览：** 页面要读取旁白音频，必须通过本地服务器打开：`python -m http.server 8765`。

## 旁白、字幕与音乐音效

画面由旁白驱动：自录旁白被自动切成 137 段对应 137 句字幕，播到哪一句，字幕和动画就走到哪一句。

**旁白对齐**

1. 旁白原长约 10 分 40 秒（639.5 秒），放在 `assets/narration.m4a`。
2. 利用句间停顿，用动态规划把录音切成 137 段，并和每句字数比对校验。
3. 每句的起止时间写入 `NARR.starts` / `NARR.ends`。录音或字幕改动后，这两组时间要一起更新。
4. 字幕比声音晚约 0.25 秒出现；关键动画按旁白中的具体词语定时，例如说到「电源」时电池才出现。
5. 10-30 改为 1.1 倍速并保持音高，整片缩短约 9%。

**人声美化**：用 Web Audio 实时处理（高通、均衡、压缩、激励、限幅），可用「美化」开关关闭。

**背景音乐**：全部在浏览器里实时合成，没有版权问题。前后约 9 轮修改，最终是：

- 轻电子、科技感，128 BPM，鼓点明确，每章转调并换不同的旋律和音色。
- 按段落切换情绪：开场、讲解、生活、明快、紧张、思考、结尾；三个事故段落改为阴沉的 D 小调。
- 说话时音乐自动压低约 2.5 dB，停顿处回升。

**音效**：元素弹出、转场、对号、错号、bug、汽车行驶、Logo 等，每句最多一个，音色偏柔和。「答案是否定的」处原本用蜂鸣声，因为太夸张改成了两音下行。

## 品牌规范

动画完成后，按 Vector 品牌要求逐项核对了字体、颜色、渐变和字幕。这些规则后来整理成了 vector-brand-style skill，供以后的作品复用。

| 方面 | 规则 | 怎么实现 |
| --- | --- | --- |
| 标题字体 | 中文 Noto Sans CJK SC Medium，英文 Clash Vector Medium | `@font-face` 用 `local()` 引用本机字体；Chrome 按家族名找不到 Clash Vector，必须写 PostScript 名 `ClashVector-Medium` |
| 正文字体 | 中文 Noto Sans CJK SC Regular，英文 Inter | 同上；英文字体排在中文前面，数字和字母走英文字体 |
| 字重 | 只用 Medium（500）和 Regular（400） | 加 `font-synthesis:none`，禁止浏览器伪造粗体；用画布和文字宽度测量确认字体真的生效 |
| 颜色 | 只用品牌色板中的颜色 | 把代码里所有自创色替换为色板中最接近的颜色；浅色底用色板颜色加透明度 |
| 渐变 | 开场、本期内容、章节目录、结束页用渐变背景，角度 30° | `linear-gradient(150deg,#000 0%,#0B1B51 45%,#F62634 88%)`；渐变页上文字和 Logo 自动变白 |
| 字幕 | 白字黑边，不加底色 | 52px，9px 描边 `#24262D`，距底部 78px |

改色时发现：低透明度的浅色放在彩色图形上会看不见（电路板、车窗、爆炸中心），这些地方改用了白色。字幕改大后自动检查了所有字幕与画面是否重叠，只有公路场景需要上移 45px。

## 导出视频

最终成片用 Camtasia 录屏得到；网页自带的「导出MP4」导出的文件在拖动进度时会出现马赛克方块，没有采用。

**网页内导出的问题**：页面用浏览器的 MediaRecorder 录制舞台。它生成的视频关键帧间隔很长，拖动进度时播放器只能从最近的关键帧解码，于是画面发花。把关键帧间隔设为 1 秒（`videoKeyFrameIntervalDuration:1000`）能缓解，但效果仍不理想。

**Camtasia 录制步骤**

1. 在装好品牌字体的电脑上启动本地预览（`python -m http.server 8765`），用 Chrome 打开动画页面。
2. 按 Ctrl+F5 刷新到最新版本，确认倍速为 1.1×，再按 F 全屏、按 H 隐藏控件；录制时鼠标不要移到屏幕底边，否则控制栏会弹出。
3. Camtasia 选择录制全屏，打开系统音频，关闭麦克风和摄像头。
4. 开始录制后按空格播放，片尾结束后停止。
5. 在 Camtasia 中剪掉头尾，导出 1080p MP4。

## 团队协作

项目放在公开仓库 [VDongzi/-HIL-](https://github.com/VDongzi/-HIL-) 上，`main` 分支受保护，所有修改都走「分支 → Pull Request → 合并」。

1. **上传：** 仓库包含动画页面、`assets/`（旁白、配图、二维码）和 README；`.claude/` 工作文件已忽略。
2. **邀请同事：** 在 Settings → Collaborators 里添加协作者。个人仓库的协作者都有写权限，包括合并 PR。
3. **分支保护：** 规则「Protect main」要求通过 PR 合并，禁止强制推送和删除 `main`，所有者也不能直接推送。
4. **协作指南：** 仓库中的 `CONTRIBUTING.md` 写明了首次准备、每次修改的命令、避免冲突的办法和项目规范。

## 经验与建议

最省时的做法是先定规范、再录旁白、最后精修画面；这次顺序反过来，导致字体、颜色和时间轴都返工过。

| 遇到的问题 | 解决办法 | 下次怎么做 |
| --- | --- | --- |
| 改完又要求回退，但没有备份 | 按对话记录重建 | 一开始就用 Git，每个改动一个提交 |
| 品牌字体、颜色事后才核对 | 全片替换 10 处颜色 | 开工前加载 vector-brand-style skill |
| 先按字数估时长，后接录音 | 自动切分录音重新定时 | 脚本定稿后尽早录旁白，画面按录音定时 |
| 浏览器录制的 MP4 拖动花屏 | 改用 Camtasia | 直接用 Camtasia 全屏录制 |
| 预览看到旧版本 | Ctrl+F5 或在地址后加 `?v=编号` | 同上 |
| 本地服务器不支持音频跳转 | 音频读成 blob 再播放 | 已内置在页面中 |
| 多人同改一个 HTML 文件容易冲突 | 按场景分工，PR 小而快 | 用 Issues 记录谁在改哪一页 |

可以直接复用的部分：场景与出现动画的框架、旁白自动对齐的方法、Web Audio 配乐与音效、品牌 skill，以及仓库的协作流程。
